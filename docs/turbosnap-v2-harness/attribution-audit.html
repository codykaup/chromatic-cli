TurboSnap v2 attribution audit

Every manifest entry treated as a coverage claim, probed for over- and under-capture across all four fixtures · measured 2026-07-30 against cody/turbosnap-v2 at 63410b78 plus the uncommitted outOfGraphFiles.ts comment (docs-only, no behaviour change) · 86 matrix probes (84 executed, 2 N/A) + 6 targeted follow-ups.

Headline

Every graph-derived and out-of-graph entry attributes correctly on vite and webpack. All 13 coverage claims hold: story hashes are exact to the importing story, <storybookConfig> and <staticFiles> catch bytes/add/delete on every fixture, the two sections stay partitioned even though .storybook/static nests inside the config dir, preview.*'s deliberate double coverage is load-bearing, <storybookVersion> is narrow as designed, and the bucket holds zero first-party files on all three non-rspack fixtures. Every entry that moved also moved storybookHash.

One new defect: symlinks under a staticDir were skipped entirely — a symlinked asset was never hashed, and a symlinked directory contributed nothing at all, so a whole vendored asset tree could be invisible. Since fixed (see G2 below): the walk now follows symlinks, with a cycle guard. Everything else found was already known, already ticketed, or has been consciously accepted.

How each verdict was reached

Each probe mutates exactly one input, regenerates the manifest from a fixed stats snapshot (so a concurrent Storybook rebuild cannot move the graph mid-run), diffs storybookHash, every per-story hash and every storybookFiles entry against a baseline taken from that same snapshot, then restores. Nothing walks the written manifest for reachability (Agreed design 6) — attribution is read, never reconstructed. The fixture repo was verified clean (git status --porcelain empty) after every run.

F. storybookHash — the top-level "did anything change?" gate

Composed at manifest.ts:190 as sorted story-hash values + sorted storybookFiles values. Every probe that moved any entry also moved storybookHash; no probe moved an entry without moving it. The gate is complete over the entries that exist.

It hashes values only, not keys, so a change that merely relabels an entry is invisible. Measured (F3): renaming a story file with identical bytes leaves the three hash values identical and storybookHash unmoved, while storyFiles' keys change. This is correct, not a gap — identical bytes mean the same title, the same story IDs and an identical render, so v2 recapturing 0 where v1 recaptures 1 is v2 being more precise. The same holds for a config-file rename (F1, storybookHash SAME): where the filename is load-bearing, as with preview.ts → preview-old.ts, a real rebuild drops the module from the stats and the .storybook/preview.ts graph entry disappears, so it is caught.

Ranked gaps

G2. Symlinks under a staticDir are skipped entirely

P1 · FIXED
Measurement
S1 — a symlinked asset in ui/.storybook/static/: hashed static-file count stays 1 → 1, <staticFiles> stays 91eac9c08be42ae6 and storybookHash stays cf35e70d6fd9c00c when the target's bytes change. It is never hashed at all.
S2 — adding a symlinked directory holding two assets: count stays 1 → 1, storybookHash SAME. The whole tree contributes nothing.
Cause
listFilesRecursively (outOfGraphFiles.ts) gates on entry.isDirectory() / entry.isFile(), both false for a symlink, and its comment claims symlinks “have no bytes of their own to hash”. That is wrong for a symlink to a file: it resolves to bytes Storybook copies and serves.
Why it matters
Distinct from G1 — this is a content miss, not a path one, so G1's acceptance does not cover it. The common monorepo pattern .storybook/static/vendor → ../../node_modules/pkg/dist makes an entire served asset tree invisible, and the assets need no accompanying source edit to change.
v1 comparison
v1 is blind too — git stores the link, not the tree, so nothing appears under the staticDirs prefix that getDependentStoryFiles.ts:287 matches. Parity holds, so per Agreed design 2 this is judged by absolute correctness, where it fails.
Fix
One line: resolve each entry with stat (following links) instead of trusting Dirent, or pass recursive with link-following, and correct the comment. Needs a cycle guard, since a symlink loop would make the walk diverge.
Resolution
Shipped as described. An entry that is neither file nor directory is resolved with stat, so a symlinked file is hashed by its target's bytes — keyed by the link's path, since that is the URL it is served at — and a symlinked directory is descended into. Each directory is resolved with realpath before it is walked, and the resolved paths are tracked, so a symlink cycle terminates; static hashing is unbounded by design, so there is no count cap to fall back on. A broken symlink contributes nothing, matching the existing configured-but-missing staticDir behaviour. Re-measured on ui: S1's <staticFiles> and storybookHash both move, and S2's hashed count goes 1 → 3. G1's two cases still report UNDER-CAPTURES, as intended.

G1. <staticFiles> is path-independent, but a static asset's identity is its URL

ACCEPTED · documented, no ticket
Measurement
Renaming an asset while keeping its bytes: storybookHash SAME on vite, webpack and rspack. Swapping two assets' contents (F2): 41406bed805f3c65 on both sides, with no source file touched at all.
Cause
rollUpHash combines content hashes in sorted-hash order (graph.ts:29), so the roll-up depends only on the multiset of contents. Correct and deliberate for modules, where identical bytes render identically; for static files the URL is the identity, so folding paths out drops the thing that matters.
Consequence
unexercised — no fixture story references a static asset by URL. The three packages with a static dir hold only mockServiceWorker.js (registered by MSW, never rendered), and marketing-ui, whose components do render images by URL prop, has no staticDirs. Only the mechanism is measured, not a changed snapshot.
Decision
Knowingly accepted, alongside the “staticDirs unresolvable” gap: the rename/swap case is exotic, a real asset change almost always arrives with a source edit that moves a story hash, and path-independence is worth keeping uniform across every roll-up. Recorded here so it is not rediscovered as new. (v1 does bail on it, so this is a knowing parity exception.)

What this audit did not cover

  • Structural graph changes — a new import, a new story file, a moved module. Every probe is content-only against a fixed snapshot by design; structural cases need a Storybook rebuild, which mutates a shared fixture.
  • The dual-importer class on more than one builder — src/theme.ts exists on ui only, so preview.*'s double coverage is verified on patched vite alone.
  • v2's bail vocabulary and production bail-rate — its own open ticket, and still blocked by v2/index.ts:72 returning fallback unconditionally.
  • Index-side comparison logic — out of scope on the map.
